Managed File Transfer, from the loading dock up

How IBM Sterling, MOVEit and GoAnywhere actually work when you're logged in as the admin — the protocols they speak, the breaches that reshaped the buyer, and where that leaves CloudFuze MFT.

PROTO

The protocols, decoded

Every MFT product is, underneath, a box that speaks one or more of these languages to move a file from one company's computer to another's. Which language a partner insists on is usually decided by their industry, not their preference — and it's the single biggest thing a new entrant has to cover to be taken seriously.

AS2 — the retail and healthcare gate

AS2 became the standard almost by decree: in the early 2000s Walmart mandated that its roughly 10,000 suppliers exchange EDI data over AS2, and other big retailers followed. That single decision is why "does it do AS2?" is a hard requirement in retail RFPs to this day. AS2 is push-only — your server has to be listening around the clock — and every message gets a signed MDN (Message Disposition Notification) back, in one of three modes: synchronous, asynchronous, or email-asynchronous. It's also popular in US healthcare specifically because it can be run in a HIPAA-compliant way, and virtually no ERP ships AS2 support natively, so buyers go looking for a dedicated AS2 gateway.

jscape.com/blog/edi-transmission, ecosio.com

OFTP2 — Europe's automotive backbone

OFTP2, released in 2007 by ODETTE (the European automotive standards body), updated the older OFTP for the internet era. Unlike AS2, it can push and pull within one session, uses digitally signed EERP/NERP receipts, supports resuming a transfer after an interruption instead of restarting it, and runs on a deliberately small command set (14 commands). To join the club you need your own OFTP2 server, real certificates, and an accredited Odette ID — or you outsource to an EDI service provider, which is what smaller shops do.

i-effect.com, ecosio.com

General knowledge — not sourced in this pass Connect:Direct, in practice, is a different animal from all of the above: it isn't an internet protocol you can implement from an RFC, it's IBM's own point-to-point software, run as a matched pair — a "PNODE" initiating and an "SNODE" receiving. Both companies install and run an actual Connect:Direct node; there's no way to "speak" it from outside without one. Its headline feature is checkpoint-restart: if a multi-gigabyte batch file breaks at 80%, it resumes at 80%, not zero — which is why banks running end-of-day settlement files over it have never had a reason to switch. This is also why it's the hardest of these seven to interoperate with as an outsider: CloudFuze can add AS2 or OFTP2 by implementing a spec and passing a certification round, but it cannot "add Connect:Direct" the same way — the realistic path is convincing the partner to run something else, not building a compatible node. PeSIT is the French equivalent of an OFTP-style protocol, still common in French banking and retail EDI; GoAnywhere publishes a short explainer on it (linked below) worth reading if you're scoping a French market push.
STER

Inside IBM Sterling

"IBM Sterling" is a family, not one product. Sterling B2B Integrator is the core integration engine; Sterling File Gateway (SFG) is the partner-facing routing layer built on top of it; Connect:Direct is the proprietary point-to-point mover described above; Secure Proxy is a DMZ gatekeeper so the real engine never faces the public internet directly. Below is what actually happens if you log into File Gateway and follow IBM's own tutorial step by step.

Four logins, four jobs

SFG ships with four pre-installed admin accounts, and the tutorial deliberately has you switch between them — separation of duties is baked into the product, not bolted on:

  • fg_sysadmin — System Administrator, owns the install itself
  • fg_architect — Integration Architect, designs the routing rules (Communities, Templates)
  • fg_provisioner — Route Provisioner, turns a template into a live route for a specific partner
  • fg_operator — Operator, the day-to-day person who watches transfers and fixes failures

ibm.com/docs — SFG tutorial, pragmaedge.com

Onboarding a partner: Community → Group → Partner

Nothing in SFG is "add a partner" as a single step. The Integration Architect first creates a Community (under Participants → Communities), which fixes how the whole relationship will behave: does the partner initiate the connection or does SFG listen for them, and over FTP or FTPS? Then a Group is created inside that community. Only after that does the Route Provisioner create the actual Partner record — with its login credentials, whether it's a producer or consumer of data, and its SSH/PGP settings — and attach it to the group.

A "transfer" is really a Routing Channel Template

There's no button labeled "create a transfer." Instead, under Routes → Templates, the architect defines a Routing Channel Template: a type (e.g. Static), a producer group and consumer group, the producer's mailbox path, a file-name pattern written as a regular expression (often just .+), and "provisioning facts" — variables like myUserId that get substituted per partner. The Route Provisioner then instantiates that template into a live Routing Channel by binding one specific producer partner to one specific consumer partner.

How a file actually moves — and how it's monitored

Partners don't log into the admin console at all. They use a separate self-service portal called myFileGateway: the producer partner logs in and drops a file into a mailbox, which fires the routing rule, and the consumer partner logs in separately to pull it out. On the ops side, the Operator's whole job is file-level search: find the file, drill into its event history and which routing channel handled it, and if something failed, hit "Replay From the Beginning of a Transfer" rather than re-doing anything by hand.

ibm.com/docs — SFG tutorial

General knowledge — not sourced in this pass Secure Proxy sits in the DMZ purely so that inbound SFTP/FTPS/AS2 sessions terminate at a hardened edge box, never at the real B2B Integrator server — conceptually the same job CloudFuze's own tls-proxy nginx profile does, just IBM-specific and heavier. Enterprises running the full Sterling stack typically treat B2B Integrator + File Gateway + Connect:Direct + Secure Proxy as one purchase, which is a large part of why Sterling deals run so large and so long to implement.
MOVE

Inside Progress MOVEit

MOVEit is really two products sold together. MOVEit Transfer is the server partners connect to (the thing CloudFuze is most directly comparable to). MOVEit Automation is a separate Windows-based workflow engine that decides when and how files move, on three trigger models: scheduled, event-driven (something arrived), or on-demand.

A "workflow" is a task built from five pieces

In Automation's Web Admin console, every job is a task made of a Source, a Process, a Destination, a Schedule, and Next Actions — no scripting required. There are three task shapes: Traditional (linear pull → process → push), Advanced (adds IF branches, FOR-each-file loops, Send Email and Run Task steps), and Synchronization (one-way or two-way folder mirroring). All of it lives on one TASKS page with Run Now, export, and bulk actions.

docs.ipswitch.com — Automation Web Admin Help (2017-era doc — verify against current release before quoting)

Failure handling, in specifics

Automation retries a failed transfer automatically, with a configurable count and timeout. It protects against grabbing a file mid-write with "partial file" detection and rename-after-upload. Integrity is checked via MD5 on plain FTP/SSH hosts, or SHA-1 with guaranteed delivery when the destination is a MOVEit Transfer host. Every transaction lands in a tamper-evident ODBC-backed log (MySQL, or Microsoft SQL Server recommended) that the built-in reporting reads from.

Two gaps worth knowing precisely

Two details stood out against CloudFuze's own feature list. First: the Automation Admin Web console has no SSO — an admin logs in with a local account, full stop. Second: SSH keys and Windows UNC credentials are protected with a FIPS 140-2 algorithm inside an encrypted XML file on the server, not a dedicated secrets vault with envelope encryption and external key sourcing the way CloudFuze's CryptoVault + SecretResolver work. Both are concrete, specific things CloudFuze already does better — worth saying plainly in competitive materials, not just implying.

Creating a task, literally step by step

Per the official guide, a Traditional task is built in exactly this order:

  1. Top menu → TASKS → Add Task (upper right) → specify a name, select Traditional, click Add Task. The task is created empty.
  2. Click Step → select Source. The Add Source dialog opens — pick how to load the source file, pick a host, click Next.
  3. The source's properties page opens; fill in its settings.
  4. Click Step again to add more elements — at minimum the task needs a Source + Destination, or a Source + Process.
  5. Click Schedule (a task with no schedule can only be run via "Run Now").
  6. Optionally attach a Next Action — Send Email or Run Task.

An Advanced task starts identically (TASKS → Add Task, name it, select Advanced) but then lets you drop in a File Loop (FOR) — repeat a set of steps once per downloaded file — and a Conditional Branch (IF) anywhere in the sequence, including nested inside a loop. Elements process top to bottom; anything indented under a FOR runs once per file, anything under an IF runs only if the condition holds.

A Synchronization task instead asks you to define Folder A and Folder B (each via its own "Add new sync folder" dialog with a host picker), starts as one-way (single arrow, A→B) until you flip it via Actions → Task Settings → Sync row → Edit, and — nice detail — lets you Actions → View Sync Preview before committing, to see exactly what the sync run would do first.

Adding a host/connector

Every source or destination has to point at a Host defined up front: HOSTS (top nav) → Add Host → pick a type (Local filesystem, UNC Share, MOVEit Transfer Server, FTP/FTPS, SSH/SFTP, POP3, SMTP, or AS1/AS2/AS3 trading-partner) → fill the type-specific fields → Add Host. Editing an existing host exposes up to a dozen tabbed categories depending on type: General, Uploads, Limits, Timeouts, Security, Proxy Server, Advanced, Directory List Parsing, Additional Commands, Firewall, Decryption, SMTP, Email MDN, Retry, Miscellaneous. Adding a host also runs a live Test connection check before you save.

GOAW

Inside Fortra GoAnywhere

GoAnywhere's whole admin experience lives in one browser-based HTML5 console, organized around Dashboards, User Management, Workflows, File Transfer Services, and Reporting — no separate portal the way Sterling splits admin console from myFileGateway.

Two kinds of users, one template system

Admin Users run the product and are scoped by Admin Roles — one person's role might let them create Projects, another's might only permit viewing audit logs. Web Users are the actual trading partners, customers, or employees exchanging files, over FTP, FTPS, SFTP, AS2, or HTTPS — and templates auto-provision a new Web User's settings and permissions so onboarding a partner doesn't mean configuring everything from scratch each time.

goanywhere.com — getting started

Building and running a workflow

Workflows are called Projects, built in the Advanced Workflows module by drag-and-drop rather than scripting — you can try this yourself in Fortra's live interactive demo, linked in the learning path below. A Project can be launched four ways: a Scheduler, a folder Monitor, a Trigger event, or someone submitting a web-based Secure Form. Once running, jobs sit in a Job Queue Manager that prioritizes and groups them, visible across Queued / Active / Completed views. Resources abstract away the actual server connection details, so the person designing a Project never sees the real credentials.

goanywhere.com — interactive demo, goanywhere.com — getting started

Security posture & deployment

GoAnywhere supports external auth against Active Directory, generic LDAP, or IBM i, SAML SSO for the HTTPS Web Client, syslog/SIEM export, an Encryption menu with dedicated OpenPGP and SSH Key Managers, folder-level encryption at rest, and a FIPS 140-3 compliance mode. It runs almost anywhere — Windows, Linux, Docker, Azure, EC2, IBM i, VMware, AIX/UNIX — plus a SaaS edition called MFTaaS, with an optional Gateway component acting as a reverse/forward proxy. Fortra also sells a Secure ICAP Gateway add-on that scans transferred files for malware and inspects/redacts sensitive content — content inspection as an upsell, not a base feature.

goanywhere.com

How it's priced

Fortra doesn't publish list prices — it's quote-only. Licensing is mostly per module/server-instance rather than per-user, with two named exceptions: Secure Mail and GoDrive are priced per user, and the AS2 client/server module is priced by number of trading partners. The standard license places no limit on how many external SFTP/FTP/HTTP(S)/SMTP/POP3 servers you connect to. A Disaster Recovery instance needs its own (discounted) license.

goanywhere.com/pricing

COUCH

Couchdrop

Worth correcting up front: this guide originally described Couchdrop as a "lighter, point-solution" gateway, flagged as unverified background guessing. Having now actually fetched its site directly, that undersold it — Couchdrop is a real, more complete MFT competitor than assumed, and it targets the same regulated verticals CloudFuze does: financial services, healthcare, supply chain, and logistics. It's also the one product in this guide with a genuinely frictionless trial — 14 days, no credit card, instant self-serve signup — which is itself a competitive data point (see GAP).

What it actually does

Couchdrop's pitch is "send, receive, and automate secure file transfers in one simple platform" — modernizing legacy MFT without code or infrastructure to run. It speaks SFTP/FTP as its primary protocols, plus AS2 for EDI, inbound webhooks, and mailbox-based (email) file receipt. Workflows are built no-code: multi-step transfer pipelines with scheduling, orchestration, and per-step actions like compression, encryption, and data transformation.

The architectural difference that actually matters

Unlike Sterling, MOVEit, GoAnywhere, or CloudFuze itself — all of which stage a file in their own storage/mailbox as part of the pipeline — Couchdrop's marketing claims files stream directly between source and destination without a temporary storage layer, and that customer data lives in the customer's own connected storage (S3, SharePoint, Google Drive, etc.), not Couchdrop's. If accurate, that's a real, structural security argument: an MFT that never holds your files at rest has a meaningfully smaller breach surface than one that does — directly relevant given the whole INCID section above is about breaches of products that did hold files at rest.

Connector catalog — the real headline number

Couchdrop connects to 50+ backends: the expected cloud storage set (SharePoint, Google Drive, Dropbox, OneDrive, Box, Egnyte, S3, Azure Blob, Google Cloud Storage, DigitalOcean Spaces, Wasabi, Backblaze B2, iDrive), enterprise systems (NetSuite, Workday), and generic SFTP/FTP/Windows/macOS servers plus custom API connectors. CloudFuze currently connects to one family (S3/MinIO) — this is the single widest gap found anywhere in this research, wider than any protocol gap.

Security & compliance — with a real certification, not just a claim

  • SOC 2 Type II — "certified, with annual third-party SOC 2 audits." Type II specifically means audited over a period of operation, not just a point-in-time design review — a meaningfully stronger claim than Type I.
  • HIPAA-ready with a signable BAA and dedicated infrastructure; GDPR audited compliance with a Data Processing Agreement available.
  • TLS 1.2+ in transit; at rest, optional hosted storage uses AES-256 via S3 SSE-C with client-side key encryption, plus full-disk encryption on Couchdrop's own servers.
  • Transfer Shield — a built-in DLP feature to "scan, classify, filter, and scrub" data in flight (no deeper technical detail published) — the same content-inspection idea as GoAnywhere's ICAP Gateway add-on, except bundled rather than sold separately.
  • Access control down to user/group/account level, plus per-protocol and per-folder restrictions; 2FA/MFA, SSO, and SCIM provisioning.
  • Continuous vulnerability scanning (via the Aikido platform) and regular independent penetration testing, published in a live Trust Center with real-time control status — a working example of exactly the kind of public trust page CloudFuze's own Trust Center is building toward.

couchdrop.io, couchdrop.io/security, couchdrop.io/pricing — fetched directly for this section

Axway, Kiteworks & the modern upstarts

This pass's searches surfaced these vendors mostly through their own compliance/positioning content rather than admin-console walkthroughs, so treat the specifics here as lighter than the three deep dives above.

Kiteworks

Kiteworks positions itself around governance and content risk more than raw protocol coverage — its own published buyer's guide and compliance guide both frame MFT primarily as a compliance and audit-logging problem, which tracks with its market reputation as leaning toward the "content firewall" / sensitive-content-governance end of MFT rather than high-volume EDI transport.

kiteworks.com — compliance guide, kiteworks.com — buyer's guide

Files.com & SFTP To Go

Files.com markets itself as a cloud-native MFT and file-sharing platform and was independently rated #1 Easiest to Use in G2's November 2025 MFT category snapshot (see the Market section) — a real, sourced signal that the modern-upstart UX bar is high. SFTP To Go, a lightweight cloud-SFTP vendor, has completed a full SOC 2 audit against the AICPA Trust Services Criteria — concrete proof that even small players now treat SOC 2 as table stakes, not a nice-to-have.

General knowledge — not sourced in this pass Axway traces back to Cyclone Commerce and is one of the oldest names in B2B integration; its MFT-relevant products are Axway B2Bi (integration/EDI engine, Sterling B2B Integrator's closest direct rival) and SecureTransport (the MFT gateway proper). Neither was a one-off. CISA's own advisory places both inside a repeated Cl0p/TA505 pattern of zero-day attacks specifically against managed file transfer products — Accellion FTA in 2020–2021, then GoAnywhere in early 2023, then MOVEit months later. MFT products are a standing target precisely because they sit at the edge of the network holding sensitive files by design; that's not an incidental risk, it's the job description. One more thing worth a critical-thinking note: SentinelOne rated the GoAnywhere CVE a CVSS 7.2 ("High"), while other trackers called it 9.8 ("Critical") — a real discrepancy across sources that's worth resolving before quoting a severity number externally.

What the RFP actually checks for

G2's own category inclusion criteria are, in effect, the buyer's checklist: multiple secure protocols (SFTP/FTPS/HTTPS/AS2/REST), automation via scheduling/triggers/workflows, real-time monitoring with failure alerts, immutable audit logs, enterprise identity integration (SSO/AD/LDAP/SCIM), compliance support (GDPR/HIPAA/PCI-DSS/SOX), and high availability.

Where incumbents are actually weak, in the reviewers' own words

Aggregated G2 reviews point to specific, exploitable pain: GoAnywhere users cite complexity (51 mentions), difficult learning curve (31), and poor customer support (18); MOVEit reviewers cite bugs, inconsistent updates, and security issues (12 mentions) — the last one landing awkwardly given 2023. On PeerSpot, GoAnywhere ranks #1 in the category (8.5 avg, 120 reviews) against MOVEit at #4 (8.4 avg, 18 reviews), though both show declining year-over-year mindshare as of PeerSpot's July 2026 snapshot — a market reviewers describe as being chipped away by newer entrants.

g2.com, peerspot.com

How it's priced, and how long a deal takes

Per G2, pricing spans free tools up to enterprise contracts worth hundreds of thousands of dollars; on-premises products are typically sold as a perpetual license plus annual maintenance, cloud MFT as a subscription. G2's own buyer advice — shortlist 3–5 vendors, run an identical-use-case demo across all of them, pilot before committing — describes exactly the sales motion CloudFuze should expect to be evaluated through.

  1. Connector breadth — the single widest gap this research found, wider than any protocol. Couchdrop connects to 50+ storage/enterprise backends; CloudFuze connects to one family (S3/MinIO). Every one of SharePoint, Google Drive, OneDrive, Box, and Azure Blob that CloudFuze can't reach is a deal Couchdrop or Files.com can win on connector breadth alone before protocols even come up.
  2. FTPS — cheapest protocol gap to close (TLS-wrapped FTP, mature libraries) and explicitly named in buyer checklists; there's no reason this isn't next.
  3. AS2 with MDN receipts — the retail/healthcare gate, and now confirmed as something a lightweight upstart (Couchdrop) already ships, not just the enterprise incumbents. Scope this as two projects, not one: implementing the protocol, and then a Drummond interoperability certification round (a recurring, scheduled, quarterly event you have to plan lead time for — see the certified-vendor list linked below). Shipping AS2 without pursuing certification will read as unfinished to a serious retail buyer.
  4. Certifications, starting with SOC 2 Type II — Couchdrop's Trust Center is the sharpest wake-up call in this whole research pass: it holds an actual, annually-audited SOC 2 Type II, not a Type I or a roadmap goal. CloudFuze's own Trust Center currently — correctly — labels its badges as goals. That gap is now closeable by a competitor a fraction of CloudFuze's apparent size, which raises the urgency here more than any other single finding.
  5. OFTP2 — lower priority unless there's an actual automotive or EU-public-sector prospect; the cost (your own OFTP2 server, certificates, an Odette ID) only pays off against a real deal.
  6. Connect:Direct interoperability — the honest answer, unchanged from earlier in this conversation: this is not a protocol CloudFuze can "add." A bank on Connect:Direct requires both sides to agree to move off it. Budget this as a sales/partnership problem, not an engineering one.

One structural idea worth stealing regardless of priority order: Couchdrop's claim of streaming files directly between source and destination without staging them in its own storage is a genuine architectural alternative to CloudFuze's current stage-in-S3/MinIO-then-forward pipeline. Worth at least a design conversation — less data at rest is a smaller breach surface, and "breach surface" is the entire thesis of the INCID section above.

Two product-shape lessons worth stealing

GoAnywhere's Advanced Workflows module is drag-and-drop, not scripted — confirm CloudFuze's own Workflows screen holds to that same no-code bar as it grows, since a visual builder is explicitly what buyers compare it against. Separately, Sterling's four-persona admin model (sysadmin/architect/provisioner/operator) is heavier than CloudFuze needs today, but it signals that enterprise buyers do expect separation-of-duties admin roles eventually — worth keeping in mind as RBAC granularity comes up in a future release, without copying Sterling's full weight.

A messaging angle, used carefully

The reviewers' own complaints — GoAnywhere's complexity and support, MOVEit's bugs and "security issues" — are fair game to contrast against a clean React console and a from-scratch security design. But CloudFuze's own Trust Center already gets the discipline right here: badges and a "zero-breach record" are marketing until the actual third-party audit exists. Given that Cl0p hit two MFT products in one year specifically because they're MFT products, an unearned claim here is the one mistake this whole research pass argues hardest against making.
